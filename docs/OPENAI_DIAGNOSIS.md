## What the code correction changes

The corrected error handler distinguishes palette and image failures, authentication, access restrictions, unavailable models, incompatible requests, billing, provider rate limits, and explicit content-policy rejection. The old code merged both request stages for 401/403 and incorrectly blamed the prompt for every 400. No automatic model fallback or repeated generation is added.

A read-only storage prerequisite check also runs inside the claimed background worker **before either OpenAI request**. The shared-bucket implementation uses existing `files.read` access to list at most one file in `circle-media` and discards the result. A missing bucket becomes `wallpaper_storage_missing`; another read failure becomes `wallpaper_storage_unavailable`. This check does not create storage, verify bucket permissions/extensions/available capacity, change a plan, or grant access. It prevents a known missing bucket from allowing a generation that cannot subsequently be saved.

The deployed `b9ed85b` version checks the old wallpaper bucket and therefore stops before OpenAI in the reported Free project. Deploying the approved shared-bucket update changes that check to the existing `circle-media` bucket. It does not repair or retest the OpenAI key/model issue. Read-only dashboard checks and the previous failure's evidence remain useful; no new generation is needed for this diagnosis.

## How to interpret the evidence

| Upstream evidence                                                                                     | Corrected Circle code       | What it means / Dot's next check                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **401** / invalid API-key identifier                                                                  | `provider_authentication`   | OpenAI did not accept authentication. Inspect existing key status and organization/project association. Code cannot repair a revoked or invalid secret.                                                                                                  |
| **403** / permission or access restriction                                                            | `provider_access`           | The request is forbidden for that key/project/organization or deployment region. Inspect endpoint permission, selected-model access, verification requirements, and any explicit provider restriction. Do not assume every 403 means image verification. |
| **404** / model not found                                                                             | `provider_model`            | The selected model may not exist under that identifier, or may be unavailable to this project. Check exact non-secret model ID and project access. Do not silently switch models.                                                                        |
| **400 or 422** / unsupported model, parameter, or value without a specific model-not-found identifier | `provider_request`          | Check the failing stage and request/model compatibility. This does not establish that the user's description was at fault.                                                                                                                               |
| Explicit recognized prompt/content-policy rejection                                                   | `provider_prompt`           | The provider rejected the requested content. Surface safe prompt guidance; do not label every 400 as a policy rejection.                                                                                                                                 |
| `insufficient_quota` / recognized billing block                                                       | `provider_billing`          | Inspect existing billing/credit/limit status without changing it.                                                                                                                                                                                        |
| **429** without a billing-specific code                                                               | `provider_rate_limit`       | Inspect retry timing and project/model limits. Circle's own wallpaper allowance is separate.                                                                                                                                                             |
| Other provider failure or unavailable transport                                                       | `provider_unavailable`      | Use safe stage/status/request metadata if present. Do not expose raw output or infer that changing the key is the fix.                                                                                                                                   |
| Missing required shared media bucket                                                                  | `wallpaper_storage_missing` | Check bucket availability and the active code version, then stop before a paid attempt. A second bucket is not required by the shared-bucket update.                                                                                                     |

Successful text-palette generation does not prove image access. Successful model listing or dashboard access does not prove that a particular generation request will succeed. A code fix can make errors accurate; it cannot grant provider access.

The stage matters: `palette` identifies the text-model request; `image` identifies image generation. Authentication, access, model, request-configuration, and billing errors are presented as server-setup failures, not as an instruction to repeatedly retry or rewrite an innocent prompt. A genuine provider rate limit retains its retry metadata. Public messages and saved failures identify the stage without copying provider message text.
